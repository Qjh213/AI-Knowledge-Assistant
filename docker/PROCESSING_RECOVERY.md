# 文档处理故障与恢复（单进程部署）

## 适用范围

当前后端使用单个 Uvicorn 进程和进程内线程池。活跃任务集合不是分布式锁。
不能在多个后端副本或多个 Uvicorn worker 下依赖“恢复处理”防重；扩容前必须改为共享任务队列和数据库租约。

## 网络故障和代码问题分别处理

- MinerU 报告完成后，后端仍需下载 ZIP、读取文本、切分并入库。
- `UNEXPECTED_EOF_WHILE_READING` 表示 TLS 连接中断，不表示 PDF 本身损坏。
- 本机已复现 Docker Desktop 配置的代理访问 `cdn-mineru.openxlab.org.cn` 失败，而 Windows 直连同一份 ZIP 成功。
- Docker Desktop 的代理例外可针对该域名配置，容器代理需继承对应配置。代码中的 `trust_env=False` 不会绕过 Docker Desktop 层的代理。
- 保留 TLS 证书验证；重试不能修复持续失败的代理链路。

## 修正后的行为

1. 只读任务查询、ZIP 下载遇到临时网络错误或指定的临时 HTTP 状态，最多尝试 3 次，重试间隔为 1、2 秒。上传和创建远端任务不自动重放。
2. 下载中断后丢弃残缺 ZIP，重新完整下载；仍执行原有下载和解压大小限制。
3. 后台异常不再静默忽略。日志包含文档 ID、处理次数、阶段和异常类型，不打印原始异常文本、签名 URL 或密钥。
4. 使用独立数据库事务保存兜底失败状态，仅更新相同处理次数且仍为 processing 的文档，不覆盖已完成、已失败或新一轮任务。
5. 结果下载失败时明确提示阶段，进度显示 99%（不代表已入库），保留远端任务 ID。
6. 重试/恢复优先沿用已有 MinerU 任务；只有查询确认远端任务失败时，才重新提交。远端任务查询失败不会盲目重新上传。

## 恢复现有残留任务

先修复下载网络，等待其他真实处理任务结束，再更新前后端镜像。
刷新页面，对长期停留 processing 的文档点击“恢复处理”并确认。
后端会拒绝恢复当前进程仍在执行或排队的任务；没有活跃任务的 processing 记录可以重新入队。
如果远端任务已经过期或不存在，先调查返回错误，不要反复点击批量重试。

兜底事务在数据库不可用时也可能失败，此时日志会明确记录失败状态保存失败。
进程被强制终止也无法执行兜底逻辑，恢复入口用于处理这类残留状态；本次修正不引入启动时自动重跑或后台定时扫描。
当前超时检查不是对所有阻塞操作的硬截止时间。

诊断和代码测试不等于线上任务已恢复；必须更新运行镜像并验证下载、恢复和最终入库结果。
